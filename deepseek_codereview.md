> Generated by DeepSeek TUI, 2026-05-10

## Critical Bugs

### 1. Non-deterministic window node IDs cause root-child mismatch
**File:** `src/background-logic.ts`, lines 291, 375

Line 291 creates new window nodes with a random suffix:
```ts
id: `win-${w.id}-${generateId()}`,
```
But line 375, when creating the root node's initial `childIds`, uses the pattern *without* the suffix:
```ts
childIds: windows.filter(w => w.id !== outlinerWindowId).map(w => `win-${w.id}`),
```
On first launch, the root's `childIds` will reference IDs like `win-101` while the actual window node's ID is `win-101-a1b2c3...`. The `isNewWindow` branch then pushes the *correct* ID, but the stale wrong ID remains in `root.childIds` permanently — the tree structure is corrupted from the first reconciliation.

**Fix:** Either remove the `generateId()` suffix from line 291 (since `w.id` is already unique per Chrome session), or use the same ID generation function in line 375.

---

### 2. Premature `safeReconcile()` call after window restore
**File:** `src/background-logic.ts`, `RESTORE_NODE` handler

After `chrome.windows.create(...)`, the handler immediately calls `safeReconcile()`. Chrome may not have finished loading tab titles/favicons by the time the reconciler queries `windows.getAll({ populate: true })`. This can cause the reconciler to capture incomplete metadata, overwriting stored titles with empty strings or `about:blank`.

**Fix:** Delay reconciliation or listen for tab completion events before reconciling.

## Medium Bugs

### 3. `w.tabs` can be undefined, silently dropping tabs from reconciliation
**File:** `src/background-logic.ts`, line 312

```ts
for (const t of (w.tabs || [])) {
```
If `chrome.windows.getAll({ populate: true })` returns a window without tabs (possible with incognito windows or during tab loading), the loop silently produces zero tab nodes. Any existing stored tabs for that window would then be marked as missing/removed.

**Fix:** Add an explicit check and log a warning when `w.tabs` is undefined or empty for a known window.

---

### 4. React state derived from props won't update
**File:** `src/App.tsx`, `NodeItem` component

```ts
const [collapsed, setCollapsed] = useState(node.type === 'window' && node.status !== 'open');
```
If the `node` prop's status changes (e.g., user restores a window from `saved` to `open`), `collapsed` stays `true` because `useState` initializer runs only once. The `forceExpand` prop partially addresses this during search, but normal status transitions leave stale collapse state.

**Fix:** Add a `useEffect` watching `node.status`, or derive `collapsed` from props rather than local state.

---

### 5. `intentionallySavedNodes` Set lacks cleanup on node deletion
**File:** `src/background-logic.ts`

The Set is cleaned when the reconciler sees the node as missing and marks it saved (lines 257, 273). But if a user uses "Remove" (trash icon) to delete a node, the node ID remains in `intentionallySavedNodes` indefinitely. Over long sessions with heavy tree editing, the Set leaks memory.

**Fix:** Add a cleanup hook triggered on node deletion, or periodically prune IDs not found in storage.

---

### 6. `reconciledWindowIds` collected but unused
**File:** `src/background-logic.ts`

The array `reconciledWindowIds` is populated during the window reconciliation loop but never read afterward. Windows that no longer exist in Chrome aren't pruned from `root.childIds` — they accumulate stale entries over time.

**Fix:** Use `reconciledWindowIds` to update `root.childIds` after the loop, removing any window IDs no longer present.

---

### 7. Stale closure in `useEffect([], ...)`
**File:** `src/App.tsx`, line ~507

```ts
useEffect(() => {
    loadTree();
    const refreshListener = () => loadTree();
    ...
    const handleKeyDown = (e: KeyboardEvent) => { ... };
    ...
}, []);
```
`loadTree` and `handleKeyDown` are defined in the component body and recreated on each render. The effect captures the *first* render's versions only. Currently harmless since the captured functions are functionally stable, but fragile if they ever close over state/props.

**Fix:** Move `loadTree` and `handleKeyDown` into the effect body, or use `useCallback` with proper dependency arrays.

## Minor Bugs & Code Quality Issues

### 8. `NodeItem` component defined inside `App`
**File:** `src/App.tsx`

The `NodeItem` component (~200+ lines) is defined within the `App` function body, causing React to treat it as a new component type on every render. This prevents structural reconciliation, resets all internal state, and makes React DevTools less useful.

**Fix:** Move `NodeItem` and `TabIcon` to the module scope. Pass `App`-level dependencies through props or context.

---

### 9. `positionalWeave` has O(n×m) complexity
**File:** `src/utils.ts`

```ts
if (activeTabIds.includes(oldId)) {
```
`includes` is O(m) on every iteration of the O(n) outer loop. For a window with 100 tabs, this is ~10,000 comparisons per reconciliation.

**Fix:** Convert `activeTabIds` to a `Set` inside the function for O(1) lookups.

---

### 10. No `chrome.tabGroups` API integration
The extension doesn't use Chrome's native Tab Groups API. User-created groups in the outliner don't map to Chrome tab groups, and Chrome-native groups are invisible to the outliner.

---

### 11. Double reconciliation on `onReplaced` event
**File:** `src/background-logic.ts`, line 223

`chrome.tabs.onReplaced` fires *in addition to* `onRemoved` + `onCreated` when a tab is replaced (e.g., prerender navigation). The reconciler runs multiple times for a single logical change.

**Fix:** Add event coalescing or debouncing.

---

### 12. No React Error Boundary
**File:** `src/App.tsx`

If any `NodeItem` throws during render (e.g., corrupt storage data), the entire tree UI crashes to a white screen.

**Fix:** Wrap the tree in an `ErrorBoundary` to contain failures to individual subtrees.

## Architectural Observations

### 16. Dual sync mechanism
Both `REFRESH_TREE` custom events and `chrome.runtime.sendMessage` `TREE_UPDATED` trigger `loadTree()`. Two paths to the same outcome is fragile — a unified state management approach would simplify.

### 17. `broadcastUpdate` sends to all extension pages
**File:** `src/background-logic.ts`, line 231

```ts
chrome.runtime.sendMessage({ type: "TREE_UPDATED" }).catch(() => {});
```
Broadcasts to *all* extension pages. If an options page or side panel is added later, all will process this message.

### 18. No optimistic updates
All mutations follow a write-then-refetch pattern. There's a visible flicker as the tree reloads from IndexedDB. Optimistic state updates would improve UX.

### 19. Missing `chrome.windows.WINDOW_ID_NONE` handling
In MV3, `chrome.windows.getAll()` can return windows with ID `-1` (panels, devtools). These aren't filtered and would produce invalid stored nodes.

## Antigravity Execution Plan

Based on the Karpathy Guidelines (Think Before Coding, Goal-Driven Execution), here is the structured execution plan to address the most critical issues:

### Phase 1: Core Data Logic Fixes
* **Goal**: Prevent data corruption and memory leaks in the reconciliation loop.
* **Bug 1**: Remove the `generateId()` random suffix from `winNode.id` creation so it correctly matches `root.childIds`.
* **Bug 3**: Check if `w.tabs` is undefined during window fetch, log a warning, and skip those windows to avoid wiping valid saved tabs.
* **Bug 6**: Use the `reconciledWindowIds` array at the end of `reconcileTabs` to filter out stale window IDs from `root.childIds`.

### Phase 2: React Architecture Fixes
* **Goal**: Resolve React performance and state staleness.
* **Bug 8**: Extract `NodeItem` and `TabIcon` out of the `App` component into the module scope.
* **Bug 4**: Change `collapsed` state to derive directly from props or update it automatically via `useEffect` tracking `node.status`.
* **Bug 7**: Move functions like `loadTree` and `handleKeyDown` out of stale closures by extracting them to stable references or moving them inside `useEffect`.

### Phase 3: Async Race Conditions
* **Goal**: Ensure Chrome APIs have finished loading before reading state.
* **Bug 2 & Bug 11**: Debounce `safeReconcile` or add specific async delays when restoring windows before we try to save their state, preventing empty snapshot overwrites.
